# 验收：结构、内容、真实页面

## 脚本检查

- 配套文件夹运行 `build_bundle.py --check`；独立 PDF 存在且 SHA-256 与原件一致，HTML 的相对链接可用，文件夹移动后仍可检查。检查记录与生成源齐全，重新构建不覆盖用户笔记。用户编辑笔记后清单变化属于新内容，应更新快照，不能回滚笔记来“通过”。
- `build_reader.py` 构建和 `--check` 都退出 0；ID 无重复、无丢块、每块有译文和三项批注，正文文本摘要匹配；五色高亮命中且未改变英文。
- 内部锚点能定位，参考文献链接不悬空。来源链接是用户主动点击才访问的外链；页面加载无外部 src、CSS import、网络字体或外部 JS。
- 所有图片和英文字体内嵌，中文使用系统字体。附带 PDF 时，浏览器下载所得文件 SHA-256 等于传入 PDF，不只检查按钮存在。
- 留存来源清单、批注 JSON 和 QA 记录。自动数量来自当前清单，不能硬编码另一篇论文的统计。

## 浏览器检查

可用现有浏览器自动化或 Playwright。自带 `scripts/browser_qa.cjs` 是可复用冒烟检查；需宿主已安装 `playwright`，可设 `READER_BROWSER_EXECUTABLE` 指向本机 Chromium/Chrome/Edge。它检查桌面/移动布局、无加载请求、搜索、语言切换、图例、锚点与 PDF 下载哈希并保存截图；不是内容审稿。

```bash
node <skill目录>/scripts/browser_qa.cjs FinTSB.html qa-output
```

实际查看桌面与移动端截图；抽检开头、中间、结尾、长表/提示框、公式与附录。英文和中文之间应有 1px 分隔线；译文米色块无高亮；每行批注与对应源块放在同一网格行。长表在局部容器滚动，整页不超宽；sticky 导航不挡住标题，键盘焦点可见，图例文字也能传达颜色含义。浏览器中间宽度同样要检查。

## 人工语义检查

逐段核对论证是否连续、数据与公式是否忠实、译文有无遗漏否定/时间/范围限定、批注是否只是复述。检查概念定义是否先于使用，证据支持的是相关还是因果，作者让步是否真的回应主要异议。底部总览必须可回指具体段落，最强/最弱各一条应有依据。
同时检查版面是否读起来割裂：连续短段是否已按小节合并；项目符号/编号是否仍为列表而不是流水段；批注是否用“这段在做什么 / 在全文里的作用 / 读的时候要留意”的人话说明，而不是术语堆叠或模板复述。

报告只写实际完成的范围：结构通过不能叫全文语义通过；无真实浏览器时说明视觉尚未验收。若有不可恢复内容，改成节选并显著标明缺失，不能交付“完整全文”标签。
